# Portland Dashboard — Accuracy & Functionality Review

**Date:** September 30, 2026  **Build reviewed:** `index.html` (data as of Sep 28, 2026)

This is an internal code and calculation review, not a third-party audit or certification.

## How it was tested

- **Code review:** three passes over the code, looking separately at calculation logic, UI behaviour, and sync/security.
- **Independent recompute:** the headline numbers were recomputed in Python straight from the embedded CoStar data and compared with what the dashboard shows. This covered:
  - Overview KPIs.
  - The top-10 submarket rent ranking.
  - Required rent per SF for each product.
  - A full development proforma.
- **Automated browser run** (Chromium, US Pacific time zone):
  - Every tab was loaded with zero script errors.
  - The Market Report was generated 360 times: every submarket and every city in both taxonomies, every product-type combination, and every class filter. No failures, and no `NaN`/`undefined`/`Infinity` in any output.
- **Dark mode:** every tab was scanned automatically for low-contrast text and checked visually.
- **Existing regression tests:** report modal, cloud sync, YOC and multi-product filter all pass.

## Verified correct

| Area | Result |
|---|---|
| Overview KPIs (Existing, all classes) | 1,700 properties · 233,401 units · $1,697 rent · $2.10/SF · 92.6% occupancy · 4.6% concessions. Matches the independent recompute exactly. |
| Unit weighting | Rent, $/SF, vacancy and concessions are weighted by units, and nulls are excluded from both numerator and denominator. |
| Required PSF (6.50% YOC, 925 SF, $2,500 other income, 5% vacancy) | Garden $3.02 · Mid-Rise $3.78 · High-Rise $5.52. Matches the recompute. |
| YOC algebra | TC = land + HC×SF + other HC + soft. NOI = (rent×12×SF + other income) × (1 − vacancy − opex). Opex is taken on gross potential, the same way in the matrix and the proforma. |
| Proforma | Checked line by line: GPR, vacancy, opex, NOI, TPC ($360,500/unit), exit value, cost of sale, profit ($23.6M), loan/equity and equity multiple (1.61x). |
| Market scoping | All reads and writes are tagged `market = 'portland'`, so there is no cross-market bleed. |
| XSS | Everything user-entered and rendered goes through `escapeHTML`. |

## Bugs found and fixed

**Would have been visible to a recipient**

1. **The Market Report failed to open** for 3 submarkets (Skamania, CBD, Outlying Multnomah) and 11 small cities. The cause was an empty rent scope. Fixed; all 360 scopes now render.
2. **Overview "Rent Distribution by Submarket" left out the true top 10.** It ranked only the 14 largest submarkets, which dropped Lake Oswego ($2.39) and Central NE ($2.02). It also mixed in under-construction rows. It now ranks every submarket on the same Existing basis as the KPIs.
3. **YOC required-rent tiles all said "30% OpEx".** They now show the ratio actually applied to each product: 30%, 28% and 25%.
4. **Report YOC overrides.** A typed OpEx % was silently ignored, and a blank cost field was treated as $0. Now a typed OpEx applies to every product, and a blank cost keeps the dashboard value.
5. **Lease-up.**
   - The window label said "Sep 2025 – Sep 2026", but Sep 2025 deliveries were excluded. That dropped Astral & Revel (594 units).
   - Months open were counted in whole months, which overstated pace.
   - Both are fixed.
   - In the report, deliveries open less than a month no longer top the pace ranking; they are footnoted instead. Broadstone Walnut Grove had shown 97/mo from pre-leasing.
6. **Trends tab.**
   - The MSA heat-map row was labelled "DENVER MSA", and the MSA also appeared a second time as a submarket row.
   - The "YoY Rent Δ" metric printed NaN.
   - Occupancy, concessions and YoY are now shown as point changes rather than a CAGR of a percentage.
   - The placeholder "Pick a submarket" option blanked the chart; it can no longer be selected.
7. **CoStar taxonomy:** the High-Rise chip returned zero properties because CoStar spells it "Hi-Rise". It now finds 49.
8. **Dates.**
   - The footer read "Sep 27" in US time zones.
   - The property history labelled live data "Q4 2026"; it is now "Q3 2026".
   - Report dates are now anchored to the data date.
9. **Dark mode:** Trends, the YOC controls, the proforma, selects and buttons had white-on-white text. All are fixed.
10. **Status = Under Construction** blanked the Overview KPIs. They now describe the UC set and are labelled that way.
11. **Leftovers from the Phoenix and Denver builds:**
    - The Opportunities map opened on Denver.
    - Geocoding appended ", AZ" to addresses.
    - The comp-set prompt suggested "North Tempe".
    - The report modal still said costs were "not repriced for Portland".
12. **Filters.**
    - "Reset filters" set the class filter to A+B instead of All.
    - Clicking a product chip could clear valid submarket or city picks.
    - The report now honours the 650 SF+ unit-size filter.
    - McMinnville appeared twice in the city list.

**Behind the scenes (cloud sync)**

13. **Comp-fee schedules entered before cloud sync was switched on were wiped on first load.** They are now uploaded instead.
14. **Comp-set boot check failed on every load.** It queried a column that doesn't exist. Fixed.
15. **Realtime listeners for WB deals and comp fees reacted to other markets' edits.** They are now filtered to Portland.
16. **"Sync now" skipped WB deals and comp fees.** It now includes them.
17. **`updated_at` triggers were added** to the two new Supabase tables, so newer-wins conflict checks work.

## Open risks — decide before sending

1. **Licensed data is public.**
   - The GitHub repo and the Pages site are public.
   - Both contain the full CoStar property export and RealPage series. Anyone with the link can download them.
   - Check the CoStar and RealPage license terms before sharing the link outside Willow Bridge.
   - Safer options:
     - Send the `index.html` file directly instead of the link.
     - Host it behind sign-in (a private repo with paid Pages, Cloudflare Access, or Netlify with password protection).
2. **Shared data is open to anyone with the page.**
   - Supabase accepts reads and writes from the key embedded in the page.
   - Someone with the link could edit or delete Portland, Phoenix or Denver shared records (edits, comp sets, opportunities).
   - This is the same setup as the Phoenix and Denver dashboards.
   - Enabling the built-in Microsoft sign-in with authenticated-only access rules would close it.
3. **Cost assumptions are placeholders.** YOC and proforma costs are Denver figures indexed to Portland (×1.165), with land at $30K/unit. Every place they are shown is labelled accordingly.
4. **Known limitations (not bugs):**
   - A record deleted on one machine can be re-uploaded by another browser that still has it cached.
   - Manual submarket edits apply in both taxonomies.
   - RealPage provides no 2026+ asking-rent or concession forecast, so those Trends views show "—".
   - South Waterfront's RealPage series maps to Southwest Portland/Tigard; RealPage places it in Central Portland.
   - Cloud sync could not be exercised live from the test environment. The schema, triggers and queries were verified directly against the database.
